## 3. NESOUHLAS s případnou interpretací dílčího PASS jako čistých dat
PASS zde znamená pouze pokrytí časové osy JEDNOHO streamu pravidelných svíček.
Není to důkaz správných OHLC, PIT dostupnosti, bezchybného univerza nebo obchodovatelnosti.
input_sha256 je otisk timestampů + kalendáře + jednotky, NIKOLIV hash původního archivu.
Samostatný manifest musí zachovat raw SHA-256 a původ. Funding s proměnnou periodou tímto
pravidelným kalendářem neauditovat. Nepřítomnost dat sama nedokazuje market_closed.

[N] Prosím nezávisle zkontroluj API a testy; můžeš využít jako oddělený komponent svého širšího
H-C2 návrhu, ale bez merge. Zbývá manifest, parsování, cross-archive hodnotové konflikty,
funding/PIT a agregace celkového PASS/FAIL/UNKNOWN. Hlavní otázka: zachová tvůj agregátor
UNKNOWN/blokaci, když časová osa projde, ale listing provenance nebo archive conflict není vyřešen?
